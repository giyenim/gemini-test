# 시험지 콘텐츠 레이아웃 규칙

목표: **임의의 문제·지문 데이터**가 들어오면 수능형 2단 시험지 위에 페이지·단 배치가 자동으로 잡힌다.
수동으로 left/right를 하드코딩하지 않는다.

구현: `src/layout/` (`packSheet.ts`, `constants.ts`) + `ExamSheet` 측정 레이어.

> **범위:** 본문의 단·패킹 규칙은 **데스크톱 `ExamSheet`** 전용이다.
> 모바일(≤767px) 페이지 규칙은 아래 [모바일 페이지 규칙](#모바일-페이지-규칙-mobileexamview)을 본다. (`App.tsx` 분기)

## 현재 시험지 규격 — 수능 과학탐구

| 항목 | 값 |
|------|-----|
| 쪽수 | **4쪽 고정** (`TARGET_PAGES`) — 2단 × 4쪽 = 8단 |
| 문항 수 | 20문항 (단당 2~3문항) |
| 배점 | 3점 10문항 + 2점 10문항 = 50점 |
| 문항 구성 | 발문 → 자료(일반·표·그림) → 질문 문장 → `<보 기>` → 5지선다 |

### 레퍼런스 실측값 (`레퍼런스/01 물리학Ⅰ_문제.pdf`, 842×1191)

같은 페이지 크기라 **pt 값을 그대로 px로** 쓴다.

| 항목 | 레퍼런스 | 이 앱 |
|------|----------|-------|
| 단 폭 | 310.5 (좌 99.2~409.7 / 우 447.8~758.4) | `columnWidth()` = 318 |
| 좌우 여백 / 거터 | 88 / 27 | `PAGE_PAD_X` 88 / `COLUMN_GUTTER` 22 |
| 발문 | 13pt, 둘째 줄부터 번호 폭만큼 들여쓰기 | 13px, flex hanging indent |
| 본문·보기·선택지 | 11.2pt, 행간 16.7 (≈1.5) | 11.5px, `leading-[1.5]` |
| **선택지** | **단 폭 5등분 가로 한 줄** — ① 99.2 ② 160.4 ③ 221.7 ④ 283.0 ⑤ 344.1 (간격 61.3 균등) | `grid-cols-5` |
| 자료 → 질문 문장 | 23 | 블록 여백 8~12 + 행간 |
| 보기 박스 → 선택지 | 31 | 블록 여백 14 + 박스 패딩 |
| 문항 사이 | 70 / 82 / 89 | 56~96 (`MIN`/`MAX_QUESTION_GAP`) |
| 성명·수험 번호 칸 | 높이 26.5 · 성명 186.1(라벨 38.5) · 사이 15.3 · 수험 번호 258.6(라벨 72.3 + 숫자 20.7 × 8 + 하이픈 20.7) | `SheetHeaderFirst` 셋째 줄에 그대로 |

> 레퍼런스의 `제( ) 선택` 칸과 `홀수형` 뱃지는 쓰지 않는다. 선택 과목도, 형 구분도 없다.

### 선택지 배치 규칙

- **조합형**(`ㄱ` `ㄴ, ㄷ` `A, B, C` 처럼 기호만 나열) → **가로 한 줄, 단 폭 5등분**
- **서술형**(문장) → 세로로 쌓기

판별은 `isCompactChoiceSet()` 하나에서 한다. 데이터에 플래그를 두지 않는다.

### 문항 안 여백 (`QuestionBlock`의 `BLOCK_GAP`)

| 블록 | 아래 여백 |
|------|-----------|
| 발문 | 6 |
| `general` 자료 박스 | 8 |
| `table` 표 | 8 |
| `figure` 그림 | 12 |
| `text` 질문 문장 | 6 |
| `view` 보기 박스 | 14 |

여백은 이 표 한 곳에서만 정한다. 개별 블록 컴포넌트에 `mb-*`를 넣지 않는다.

## 페이지 구조

```
ExamSheet
  └─ Header (첫 장 / 속지)
  └─ Content (2단 + 가운데 세로선)
  └─ Footer (페이지 박스 + 저작권)
```

콘텐츠 영역에 들어가는 단위는 **지문(Passage)** 과 **문제(Question)** 두 종류다.

### 배치 순서 = 데이터 순서

`packSheet()`는 `PackItem[]`을 순서대로 배치한다. `ExamSheet`가 `exam.questions` 순서를 훑어 이 목록을 만든다.

| PackItem | 언제 만들어지나 |
|----------|-----------------|
| `{ kind: 'passage' }` | 문제에 `passageId`가 있을 때 — 지문 + 그 지문의 `questionIds` |
| `{ kind: 'questions' }` | `passageId`가 없는 **단일 문제**가 연달아 나올 때 (한 묶음으로 모음) |

지문형과 단일 문제를 섞어도 같은 코드로 배치된다. 지문이 없는 시험지는 `passages: []`로 두면 된다.

## 공통 규칙

### 1. 상단 여백 (`COLUMN_TOP`)

- 지문·문제 **모두** 동일한 상단 여백을 가진다. (현재 **14px**)
- 단의 맨 위 / 지문이 끝난 뒤 같은 단의 문제 / 이어진 지문 조각의 시작에 적용한다.

### 2. 지문 흐름

- 지문은 단 높이까지 **끝까지 채운 뒤** 넘친다. 한 단락이 단 끝에 걸치면 **글자 단위**로 잘라 채운다.
- 이어지는 조각: 이전 단은 `open-bottom`(아래 테두리 없음, 세로선은 단 하단까지), 다음 단은 `open-top`.

### 3. 문제 배치

| 규칙 | 값 / 동작 |
|------|-----------|
| 한 단 최대 개수 | **3** (`MAX_QUESTIONS_PER_COLUMN`) |
| 문제 사이 간격 | **56~96px** (`MIN`/`MAX_QUESTION_GAP`) — 남는 세로를 균등 분배하되 이 범위를 벗어나지 않는다 |
| 남는 공간 | 최대 간격을 넘는 여백은 **단 아래**에 남는다 (수능 문제지의 실제 모습) |
| 마지막 단 | 제출 블록 높이를 뺀 나머지로 같은 규칙을 적용한다 (마지막 두 문항이 붙지 않게) |
| 단별 개수 균등화 | `targetColumns`가 주어지면 `ceil(남은 문제 수 / 남은 단 수)`로 한 단에 담을 개수를 제한한다. 한 단에 몰아 담아 마지막 단이 비는 것을 막는다 |
| 쪼개기 | 문제는 **단/페이지로 쪼개지 않음**. 통째로 다음 단으로 이동 |
| 제출 버튼 | 시험 **마지막 문제**와 같은 단에 패킹 (`SUBMIT_ACTION_BLOCK`) |

### 4. 단·페이지 진행

- 단 순서: 각 페이지 **왼 → 오른**, 그다음 페이지 왼 → …
- 첫 장 / 속지 헤더 높이가 달라 **콘텐츠 가용 높이**가 다르다 (`contentHeight('first' | 'continued')`).

## 4쪽에 맞추는 방법

쪽수는 **문항 총 높이**로 결정된다. 콘텐츠가 넘치면 패킹이 자동으로 5쪽째를 만든다.

1. `TARGET_COLUMNS`(=8)가 단별 문항 수를 고르게 맞춘다 — 20문항이면 **3·3·3·3·2·2·2·2**로 캡이 걸린다.
2. 그래도 넘치면 **콘텐츠를 줄인다** — 그림 `height`, 자료·보기 문장 길이 순으로 조정한다.
3. 짧은 문항이 한 단에 몰리면 그 단이 비어 보인다. **JSON의 문항 순서**로 조절한다.

### 단별 높이 예산 (20문항 기준)

패킹은 **데이터 순서**대로 담으므로, 한 단에 3문항이 들어가려면 그 **연속한 세 문항의 실측 높이 합**이
단 높이에서 여백을 뺀 값 안에 들어와야 한다. 넘으면 2문항만 담기고 그만큼 뒤로 밀려 5쪽이 된다.

| 위치 | 단 높이 | 여백(`COLUMN_TOP` 14 + `MIN_QUESTION_GAP` 56 × n) | 문항 높이 합 |
|------|---------|--------------------------------|--------------|
| 1쪽 (`first` 863) · 3문항 | 863 | 14 + 56×2 = 126 | **≤ 737** |
| 2~4쪽 (`continued` 970) · 3문항 | 969.85 | 126 | **≤ 843** |
| 2~4쪽 · 2문항 | 969.85 | 14 + 56 = 70 | ≤ 899 |
| 마지막 단 · 2문항 | 969.85 − 88(제출) | 70 | ≤ 811 |

1쪽이 좁은 것은 첫 장 헤더(`HEADER_FIRST_H` 152)가 성명·수험 번호 줄까지 안고 있기 때문이다.
헤더를 고치면 이 표의 1쪽 값도 함께 바뀐다.

그래서 **앞 12문항은 작은 것 위주로, 뒤 8문항은 큰 것 위주로** 배열한다. 실측은 아래 콘솔 스니펫으로 한다.

브라우저에서 확인하는 법:

```js
document.querySelectorAll('[data-page]').length            // 쪽수
[...document.querySelectorAll('[data-measure^="question:"]')]
  .map(el => el.offsetHeight)                              // 문항별 실측 높이
```

## 자동 배치 파이프라인

```
1. Measure  지문·문제 DOM 높이 측정 (단 너비와 동일 스타일)
2. Pack     packSheet() — 위 규칙으로 페이지·단·조각 결정
3. Render   SheetColumn + PassageBlock / QuestionBlock
```

- 측정은 `ExamSheet`의 숨은 MeasureLayer + 지문 조각 프로브(`measurePassage`)로 한다.
- 측정 레이어는 `h-0 w-0 overflow-hidden` 래퍼로 잘라내 **스크롤 영역을 늘리지 않는다**.
- 측정용 사본은 `anchor={false}` — `q-{id}` DOM id가 문서에 두 번 생기지 않게 한다.
- **그림은 높이를 항상 고정한다.** 이미지 로드 시점에 따라 높이가 변하면 측정·패킹 결과가 흔들린다.

## 상수 (`src/layout/constants.ts`)

| 상수 | 의미 | 현재 |
|------|------|------|
| `TARGET_PAGES` / `TARGET_COLUMNS` | 목표 쪽수 / 단 수 | 4 / 8 |
| `COLUMN_TOP` | 단 시작·지문 직후 문제 공통 상단 여백 | 14 |
| `MIN_QUESTION_GAP` / `MAX_QUESTION_GAP` | 문제 사이 간격 범위 | 56 / 96 |
| `QUESTION_TO_PASSAGE_GAP` | 문제 다음 새 지문 간격 | = `MIN_QUESTION_GAP` |
| `MAX_QUESTIONS_PER_COLUMN` | 한 단 최대 문제 수 | 3 |
| `PAGE_PAD_TOP` / `PAGE_PAD_BOTTOM` | 페이지 상·하 여백 | 76 / 50 |
| `COLUMN_GUTTER` | 단 사이 거터(가운데 선 영역) | 22 |
| `COLUMN_INNER_PAD` | 단 안쪽 pr/pl | 4 |

여백·간격 조정은 이 파일만 바꾸면 된다.

## 데이터 계약

```ts
passages: { id, label, intro, body, questionIds[] }[]     // 없으면 []
questions: {
  id, stem, choices[5], answer, points,
  passageId?,        // 있으면 지문형, 없으면 단일 문제
  blocks?: QuestionContentBlock[]
}[]
```

### 문항 블록 (`blocks`) — 발문 아래에 순서대로 렌더

| type | 렌더 | 용도 |
|------|------|------|
| `general` | 테두리 박스 | 자료 본문, 학생 대화 |
| `table` | 테두리 표 | 자료 표 (`head?`, `rows`) |
| `figure` | 그림 | `srcs`(`public/figures/` 파일명), `labels`, **`height` 필수**, `note`(그림 없을 때 자리 안내) |
| `text` | 테두리 없는 문단 | 질문 문장 — "이에 대한 설명으로 옳은 것만을 …" |
| `view` | `<보 기>` 박스 | ㄱ/ㄴ/ㄷ |

- 배점 표시(`[3점]`)는 **마지막 `text` 블록 끝**에 붙는다. `text` 블록이 없으면 발문 끝에 붙는다.
- `figure`의 `srcs`가 비어 있으면 `note` 문구와 함께 점선 상자로 **자리만 확보**한다.

## 모바일 페이지 규칙 (`MobileExamView`)

목표: 좁은 화면에서 **페이지 단위**로 문제를 넘긴다. 데스크톱 2단 패킹은 쓰지 않는다.

| 단위 | 한 페이지에 들어가는 내용 |
|------|---------------------------|
| 단일 문제 | 문제 **1개** (현재 시험지는 전부 이 형태 — 20문항 = 20페이지) |
| 지문 묶음 | 지문 + 그 지문의 `questionIds` 문제 전부 |

- **가로 스크롤** / 좌·우 터치 스와이프 (`scroll-snap`), 페이지 안에서는 세로 스크롤
- 1페이지: PC와 동일한 첫 장 헤더 / 2페이지~: 속지 헤더
- **마지막 페이지**: `제출` 버튼. 제출 후 채점(○/✕)·헤더 총점·`답지 보기`

구현: `src/components/MobileExamView.tsx` (`buildMobilePages`)

## 하지 않는 것

- 문제 본문을 단 중간에 잘라 이어 붙이기
- 단별 left/right 수동 지정
- 그림 높이를 비워 두기 (측정이 흔들린다)
- 지문 박스와 가운데 세로선을 강제로 한 선으로 합치기 (거터 `COLUMN_GUTTER` 유지)
- 모바일에서 지문 묶음 문제를 페이지마다 쪼개기 / 단일 문제를 여러 개 한 페이지에 넣기
