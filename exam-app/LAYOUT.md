# 시험지 콘텐츠 레이아웃 규칙

목표: **임의의 문제·지문 데이터**가 들어오면 수능형 2단 시험지 위에 페이지·단 배치가 자동으로 잡힌다.
수동으로 left/right를 하드코딩하지 않는다.

구현: `src/layout/` (`packSheet.ts`, `constants.ts`) + `ExamSheet` 측정 레이어.

> **범위:** 본문의 단·패킹 규칙은 **데스크톱 `ExamSheet`** 전용이다.
> 모바일(≤767px) 페이지 규칙은 아래 [모바일 페이지 규칙](#모바일-페이지-규칙-mobileexamview)을 본다. (`App.tsx` 분기)

## 현재 시험지 규격 — 수능 과학탐구

| 항목 | 값 |
|------|-----|
| 쪽수 | **4쪽 고정** (`TARGET_PAGES`) — 2단 × 4쪽 = 8단 |
| 문항 수 | 20문항 (단당 2~3문항) |
| 배점 | 3점 10문항 + 2점 10문항 = 50점 |
| 문항 구성 | 발문 → 자료(일반·표·그림) → 질문 문장 → `<보 기>` → 5지선다 |

### 레퍼런스 실측값 (수능 과탐 물리학Ⅰ 문제지 실측, 842×1191 — 원본 PDF는 저장소에서 내렸고 수치는 아래 표가 원본이다)

같은 페이지 크기라 **pt 값을 그대로 px로** 쓴다.

> 레퍼런스의 `제( ) 선택` 칸과 `홀수형` 뱃지는 쓰지 않는다. 선택 과목도, 형 구분도 없다.

> **부정 발문은 부정어에 밑줄을 긋는다.** `옳지 <u>않은</u> 것은?`처럼 놓치면 정반대로
> 푸는 문항이라 수능 문제지는 부정어만 밑줄로 표시한다. 규칙은 `examText.tsx`의
> `NEGATION` 한 곳에 있고, `QuestionBlock`의 `renderText`로 발문과 질문 문장 양쪽에
> 적용된다. 밑줄은 `text-decoration`이라 글자 높이를 바꾸지 않아 **측정·패킹에 영향이 없다.**

> **굵은 서체는 문항 번호에만 쓴다.** 레퍼런스 4쪽 전체에서 견명조가 쓰인 곳은 문항 번호,
> 페이지 번호, `제4 교시`뿐이다. `<보 기>` 라벨 · 표 머리 · 선택지 번호는 모두 보통 굵기다.

### 배경

시험지 밖 바탕은 시험지와 **같은 흰색**에 옅은 모눈을 깐 책상이고, 그 위에 교재 표지를
벽지처럼 깔았다 (`index.css`의 `--color-desk` / `--color-desk-grid` / `--desk-wallpaper`).
종이와 배경을 **색으로는** 나누지 않으므로 경계는 모눈선이 끊기고 표지 무늬가 가려지는
자리로 드러난다. 한 번에 한 쪽만 그리므로 쪽 사이 구분선은 없다.

벽지는 `public/desk-wallpaper.webp` 한 장 — 표지 두 권을 대각으로 놓은 이음매 없는 타일이다.
타일 한 변이 모눈 20px 의 배수라 무늬와 모눈이 어긋나지 않는다.

**무늬를 손보는 곳은 CSS 가 아니라 `tools/make_desk_wallpaper.py` 한 곳뿐이다.**
`background-image` 에는 opacity 가 없어 연하기는 타일에 구워 두었고, 크기도 타일의 실제
픽셀 크기를 그대로 쓴다 (`background-size: auto`). 값을 고쳐 다시 구우면 CSS 는 손댈 곳이 없다.

| 상수 | 뜻 |
|------|-----|
| `COVER_W` | 책 한 권의 가로 — 줄이면 책만 작아진다. 제목까지 읽히게 하려면 90 이상 |
| `TILE_W` / `TILE_H` | 책 사이 간격 — 키우면 책은 그대로 두고 사이만 벌어진다 (20의 배수) |
| `ALPHA` | 진하기 — `--alpha` 로도 덮어쓴다 |
| `TILT` | 기울기(도) — 두 권 모두 같은 쪽으로 눕힌다 |

지금 값은 스크립트에서 본다 — 여기 베껴 두지 않는다. 조절할 때마다 낡는다.

### 표지

문제 페이지 앞에 **표지 한 장**이 붙는다 (`components/CoverSheet.tsx`).
페이지 규격·여백은 `constants.ts` 와 같은 값을 쓴다.

- 표지는 **쪽 번호를 받지 않는다.** 문제 페이지가 1쪽부터 시작해야 한다.
- 표지에는 `data-page` 를 달지 않고 `data-cover` 를 단다.
  쪽수 검사 `document.querySelectorAll('[data-page]').length === 4` 가 표지를 세면 안 된다.
- 패킹 대상이 아니다. 높이가 고정된 한 장이라 문제 배치에 영향을 주지 않는다.
- 모바일에서는 가로 스와이프의 첫 페이지이며, 842px 디자인을 화면 폭에 맞춰 통째로 축소한다.

### 한 번에 한 쪽

데스크톱은 **표지 포함 5쪽을 한 장씩** 보여 준다 (`App.tsx` 의 `pageIndex`, `PageNav`).
스크롤로 쭉 이어 붙이지 않는다 — 시험지는 쪽으로 끊어 읽는 물건이다.

- 쪽 넘김 버튼은 **화면 좌우 가장자리**에 고정된 손그림 버튼이다 (`PageNav` +
  `ui/PageTurnButton`). 양 끝에서는 버튼을 숨기는 대신 문구를 바꾼다 (`첫 페이지` /
  `마지막 페이지`). 표지에서 서명 전에는 오른쪽 버튼이 `이름을 쓰세요` 가 되어 서명 창을 연다.
- 방향키 `←` `→` 로도 넘어간다. 서명 창이 떠 있으면 넘기지 않는다.
- A4 비율이라 한 쪽이 화면보다 세로로 길다. **쪽 안에서는 스크롤**하고 쪽 사이만 버튼으로 넘긴다.
  쪽 전체를 화면에 맞추면 본문이 8px 아래로 떨어져 읽을 수 없다.
- 답안은 `App` 이 들고 있으므로 쪽을 넘겨도 고른 답이 남는다.
- 모바일은 이 방식을 쓰지 않는다 — 기존 가로 스와이프(1문제 1페이지) 그대로다.

### 화면 배율 (조판과 무관)

`App.tsx`의 `SHEET_ZOOM`이 **화면에 보여 줄 최대 배율**이다 (현재 **1** — 확대하지 않는다).
화면이 넓으면 이 값까지 키우고, 좁으면 폭에 맞춰 줄인다. 레이아웃은 항상 842×1191 원래
크기로 계산한 뒤 CSS `zoom` 으로 확대한다 (아래 [화면 배율 — zoom](#화면-배율--zoom-transform-아님) 참고).

> 1 로 둔 것은 **시험지 위의 것과 시험지 밖의 것이 같은 자로 재지게** 하기 위해서다.
> 쪽 넘김 버튼(`PageNav`)은 확대 밖에 고정돼 있어서, 배율을 걸면 시험지 안의 제출 버튼만
> 그만큼 커진다. 전에는 글자·점·획을 배율로 되나눠 맞췄지만, 배율을 1 로 두면 그럴 일이 없다.
> 배율을 다시 올릴 거라면 그 되나누기부터 되살려야 한다.

배율 계산은 **스크롤 컨테이너(`stageScrollRef`)의 `clientWidth`** 를 기준으로 한다.
바깥 래퍼를 재면 `scrollbar-gutter`로 잡아 둔 세로 스크롤바 자리가 빠지지 않아 가로 스크롤이 생긴다.

### 본문 글자 크기

본문은 **11.5px**이다 (레퍼런스 11.2에 가깝다).
크기는 아래 파일에 흩어져 있으니 바꿀 때 **한꺼번에** 고친다 — 측정 레이어가 빠지면 패킹이 어긋난다.

| 값 | 위치 |
|----|------|
| `text-[11.5px]` 본문 | `SheetContent` · `QuestionBlock`(발문·질문 문장) · `GeneralBlock` · `ViewBox` · `ChoiceGroup` · `PassageBlock` · **`ExamSheet`(MeasureLayer·지문 프로브)** · `MobileExamView` |
| `text-[13px]` 문항 번호 | `QuestionBlock` |
| `text-[11px]` 표 | `TableBlock` |
| `text-[10.5px]` 그림 라벨·안내 | `FigureBlock` |

**12.5px까지 올리면 1쪽 첫 단 여유가 17px만 남아** 한 줄만 늘어도 5쪽이 된다. 12px이 실질 상한이다.

### 본문 들여쓰기

문항 본문은 **단 왼쪽에서 11.3px 들여쓴 기준선** 위에 놓인다. 자료·보기 박스와 선택지까지 전부 이 선에 맞춘다.
**문항 번호만** 그 왼쪽으로 내밀어 단 왼쪽 끝에 걸린다 (hanging indent).

```
│1.  제미나이 [설정] 메뉴에 대한 설명으로 옳지 않은 것   ← 첫 줄: 번호 뒤 7.8
│    은?                                                ← 둘째 줄부터 기준선(11.3)
│    ┌──────────────────────────────────────┐
│    │ 자료 박스                              │           ← 박스도 기준선
│    └──────────────────────────────────────┘
│     이에 대한 설명으로 옳은 것만을 …                    ← 질문 문장 첫 줄만 한 글자 더(10.3)
│    른 것은? [3점]
│    ① …    ② …                                        ← 선택지도 기준선
```

`article`에 `paddingLeft`를 주고, 발문 `h3`만 `marginLeft`/`textIndent`로 되돌린다.
값은 `QuestionBlock`의 `BODY_INDENT` · `NUMBER_GAP` · `SENTENCE_INDENT` 한 곳에서만 정한다.

#### 보기 박스 (`ViewBox`)

`<보 기>` 라벨은 **윗선 위에 걸친다.** 아래 테두리가 있는 별도 머리줄이 아니다.

```
        ────────────<보  기>────────────
        │ ㄱ. …                        │
        │ ㄴ. …                        │
        └──────────────────────────────┘
```

레퍼런스 실측(2쪽 좌단) — 윗선 `99.1~229.8` / `274.8~405.5`로 **가운데가 끊겨** 있고,
라벨 `229.6~275.0`이 선(y 598.9)을 가로지른다. 첫 항목 글자는 윗선에서 **14.0** 아래.
구현은 흰 배경 라벨을 `absolute`로 얹어 선을 끊는다 (실측 대비 라벨 폭 44.8/45.4 · 첫 항목 13.9/14.0).

#### 박스 안 머리표 (`BodyLines`)

`ㄱ.` `A:` `❶` 처럼 머리표로 시작하는 줄은 **이어지는 줄이 머리표 아래로 파고들지 않는다.**
레퍼런스 실측 — `ㄷ.`가 456.4에서 시작할 때 넘친 줄은 474.4, 즉 `ㄷ. ` 다음 글자에 맞춘다.

```
ㄷ. 사람이 p에 작용하는 힘과 p가 사람에게 작용하는 힘은
    작용 반작용 관계이다.
```

머리표 폭이 종류마다 다르므로(`ㄱ.` `A:` `❶`) 고정 들여쓰기 대신 **머리표/본문 두 칸 flex**로 자동으로 맞춘다.
자료 박스(`GeneralBlock`)와 보기 박스(`ViewBox`)가 같은 `BodyLines`를 쓴다.

### 본문 정렬 · 줄바꿈

- **오른쪽 흘림**이다. `text-justify`를 쓰지 않는다 — 레퍼런스 문제지도 흘림이고(행 끝 x좌표 373~409로 제각각),
  단 폭이 318px로 좁아 양쪽 정렬을 하면 어절 사이가 크게 벌어진다.
- **줄바꿈은 낱말 중간에서도 끊는다.** `break-keep`(어절 단위)을 쓰지 않는다 — 줄이 끝까지 차서
  흘림인데도 오른쪽 끝이 고르게 보인다.
- 이 두 규칙은 **단 래퍼에서 상속**된다 (`SheetContent`). 개별 블록에 정렬·줄바꿈 유틸리티를 넣지 않는다.

> **측정 레이어와 반드시 같이 고친다.** `ExamSheet`의 MeasureLayer(`text-[11.5px] leading-[1.48] break-words`)와
> 지문 프로브(`inner.className`)가 `SheetContent`·`PassageBlock`과 다른 클래스를 가지면
> 측정 높이와 실제 높이가 어긋나 패킹이 깨진다. 모바일(`MobileExamView`)도 같은 클래스를 쓴다.

### 선택지 배치 규칙

- **조합형**(`ㄱ` `ㄴ, ㄷ` `A, B, C` 처럼 기호만 나열) → **가로 한 줄, 단 폭 5등분**
- **서술형**(문장) → 세로로 쌓기

판별은 `isCompactChoiceSet()` 하나에서 한다. 데이터에 플래그를 두지 않는다.

### 문항 안 여백 (`QuestionBlock`의 `BLOCK_GAP` / `CHOICE_GAP`)

여백은 **자리에 따라 두 값**을 쓴다. 문제 안(발문·자료·질문 문장·보기)은 넉넉하게 띄우고,
**선택지 바로 위**는 좁게 둔다 — 선택지가 문제에서 떨어져 보이면 문항 경계가 흐려진다.

| 블록 | 다음 블록 앞 (`BLOCK_GAP`) | 선택지 앞 (`CHOICE_GAP`) |
|------|------|------|
| 발문 | 9 (`STEM_GAP`) | 6 (`STEM_TO_CHOICE_GAP`, 블록이 없는 문항) |
| `general` 자료 박스 | 11 | 8 |
| `table` 표 | 11 | 8 |
| `figure` 그림 | 15 | 12 |
| `text` 질문 문장 | 9 | 6 |
| `view` 보기 박스 | 17 | 14 |

`CHOICE_GAP`은 **마지막 블록에만** 적용된다. 여백은 이 표 한 곳에서만 정한다 —
개별 블록 컴포넌트에 `mb-*`를 넣지 않는다.

## 페이지 구조

```
ExamSheet
  └─ Header (첫 장 / 속지)
  └─ Content (2단 + 가운데 세로선)
  └─ Footer (페이지 박스 + 저작권)
```

콘텐츠 영역에 들어가는 단위는 **지문(Passage)** 과 **문제(Question)** 두 종류다.

### 배치 순서 = 데이터 순서

`packSheet()`는 `PackItem[]`을 순서대로 배치한다. `ExamSheet`가 `exam.questions` 순서를 훑어 이 목록을 만든다.

| PackItem | 언제 만들어지나 |
|----------|-----------------|
| `{ kind: 'passage' }` | 문제에 `passageId`가 있을 때 — 지문 + 그 지문의 `questionIds` |
| `{ kind: 'questions' }` | `passageId`가 없는 **단일 문제**가 연달아 나올 때 (한 묶음으로 모음) |

지문형과 단일 문제를 섞어도 같은 코드로 배치된다. 지문이 없는 시험지는 `passages: []`로 두면 된다.

## 공통 규칙

### 1. 상단 여백 (`COLUMN_TOP`)

- 지문·문제 **모두** 동일한 상단 여백을 가진다. (현재 **14px**)
- 단의 맨 위 / 지문이 끝난 뒤 같은 단의 문제 / 이어진 지문 조각의 시작에 적용한다.

### 2. 지문 흐름

- 지문은 단 높이까지 **끝까지 채운 뒤** 넘친다. 한 단락이 단 끝에 걸치면 **글자 단위**로 잘라 채운다.
- 이어지는 조각: 이전 단은 `open-bottom`(아래 테두리 없음, 세로선은 단 하단까지), 다음 단은 `open-top`.

### 3. 문제 배치

| 규칙 | 값 / 동작 |
|------|-----------|
| 한 단 최대 개수 | **3** (`MAX_QUESTIONS_PER_COLUMN`) |
| 문제 사이 간격 | **56~96px** (`MIN`/`MAX_QUESTION_GAP`) — 남는 세로를 균등 분배하되 이 범위를 벗어나지 않는다 |
| 남는 공간 | 최대 간격을 넘는 여백은 **단 아래**에 남는다 (수능 문제지의 실제 모습) |
| **줄 맞춤** | 문제만 담긴 페이지는 패킹 뒤 `alignQuestionRows()`가 줄 높이를 **두 단의 최대값**으로 통일해 n번째 문제가 양 단에서 같은 높이에서 시작한다. 빠듯한 페이지는 간격을 `MIN_ALIGNED_GAP`(40)까지 좁혀서라도 맞추고, 그마저 안 되면 단별 배치를 그대로 둔다. 지문이 낀 단은 줄 개념이 없어 제외 |
| 마지막 단 | 제출 블록 높이를 뺀 나머지로 같은 규칙을 적용한다 (마지막 두 문항이 붙지 않게) |
| 단별 개수 균등화 | `targetColumns`가 주어지면 `ceil(남은 문제 수 / 남은 단 수)`로 한 단에 담을 개수를 제한한다. 한 단에 몰아 담아 마지막 단이 비는 것을 막는다 |
| 쪼개기 | 문제는 **단/페이지로 쪼개지 않음**. 통째로 다음 단으로 이동 |
| 제출 버튼 | 시험 **마지막 문제**와 같은 단에 패킹 (`SUBMIT_ACTION_BLOCK`). 그 단의 **오른쪽 맨 아래**에 붙는다 — 마지막 문제 바로 밑이 아니라 단 바닥이다 |

### 화면 배율 — `zoom`, `transform` 아님

시험지는 A4 기준(842×1191)으로 조판하고 화면 폭에 맞춰 확대·축소한다(`App.tsx`의 `SHEET_ZOOM`).
이때 **`transform: scale` 이 아니라 `zoom` 을 쓴다.**

`scale` 은 11.5px 로 조판한 글자를 늘리는 것이라 획이 픽셀 격자에 어긋나 회색으로 번진다.
같은 문장·같은 글꼴로 재면 번짐 픽셀 비율이 `scale` 48.0% → `zoom` 42.9% 로 떨어진다.
42.9% 는 확대를 아예 안 했을 때와 같은 값이다 — 확대로 생기던 번짐이 사라졌다는 뜻이다.

`zoom` 은 레이아웃을 다시 계산하므로 **배율을 건드리면 쪽수를 다시 재야 한다.**
길이가 모두 같은 비율로 늘어나 줄바꿈은 유지되지만, 보장된 것은 아니다.

### 4. 단·페이지 진행

- 단 순서: 각 페이지 **왼 → 오른**, 그다음 페이지 왼 → …
- 첫 장 / 속지 헤더 높이가 달라 **콘텐츠 가용 높이**가 다르다 (`contentHeight('first' | 'continued')`).

## 4쪽에 맞추는 방법

쪽수는 **문항 총 높이**로 결정된다. 콘텐츠가 넘치면 패킹이 자동으로 5쪽째를 만든다.

1. `TARGET_COLUMNS`(=8)가 단별 문항 수를 고르게 맞춘다 — 20문항이면 **3·3·3·3·2·2·2·2**로 캡이 걸린다.
2. 그래도 넘치면 **콘텐츠를 줄인다** — 그림 `height`, 자료·보기 문장 길이 순으로 조정한다.
3. 짧은 문항이 한 단에 몰리면 그 단이 비어 보인다. **JSON의 문항 순서**로 조절한다.

### 단별 높이 예산 (20문항 기준)

패킹은 **데이터 순서**대로 담으므로, 한 단에 3문항이 들어가려면 그 **연속한 세 문항의 실측 높이 합**이
단 높이에서 여백을 뺀 값 안에 들어와야 한다. 넘으면 2문항만 담기고 그만큼 뒤로 밀려 5쪽이 된다.

여백은 위아래(`COLUMN_TOP` 14 + `COLUMN_BOTTOM` 14)와 문제 사이(`MIN_QUESTION_GAP` 56 × n)다.
아래 값은 `PAGE_PAD_TOP` 64 / `PAGE_PAD_BOTTOM` 44 기준이다 — 이 둘을 만지면 표 전체가 움직인다.

| 위치 | 단 높이 | 여백 | 문항 높이 합 |
|------|---------|------|--------------|
| 1쪽 (`first` 881) · 3문항 | 881 | 28 + 56×2 = 140 | **≤ 741** |
| 2~4쪽 (`continued` 988) · 3문항 | 987.85 | 140 | **≤ 848** |
| 2~4쪽 · 2문항 | 987.85 | 28 + 56 = 84 | ≤ 904 |
| 마지막 단 · 2문항 | 987.85 − 88(제출) | 84 | ≤ 816 |

1쪽이 좁은 것은 첫 장 헤더(`HEADER_FIRST_H` 152)가 성명·수험 번호 줄까지 안고 있기 때문이다.
헤더를 고치면 이 표의 1쪽 값도 함께 바뀐다.

그래서 **앞 12문항은 작은 것 위주로, 뒤 8문항은 큰 것 위주로** 배열한다. 실측은 아래 콘솔 스니펫으로 한다.

브라우저에서 확인하는 법:

```js
document.querySelectorAll('[data-page]').length            // 쪽수
[...document.querySelectorAll('[data-measure^="question:"]')]
  .map(el => el.offsetHeight)                              // 문항별 실측 높이
```

### 쪽수 확인

화면에는 한 번에 한 쪽만 그려지므로(위 [한 번에 한 쪽](#한-번에-한-쪽)) 눈으로 세기 어렵다.
총 쪽수는 `App` 의 `totalPages`(= 문제 쪽수 + 표지 1)에 있고, 쪽 넘김 버튼이 마지막 쪽에서
`마지막 페이지` 로 바뀌는 것으로도 알 수 있다.

여백 상수를 만졌으면 **반드시 다시 센다.** 사람이 넘겨 보는 대신, `npm run dev` 를 띄우고
헤드리스 브라우저로 확인할 수도 있다 — `App` 의 겉 `div` 에 `data-total-pages={totalPages}` 를
잠깐 붙이고 `chrome --headless --dump-dom` 으로 받아 읽으면 된다 (확인 뒤 되돌린다).

## 자동 배치 파이프라인

```
1. Measure  지문·문제 DOM 높이 측정 (단 너비와 동일 스타일)
2. Pack     packSheet() — 위 규칙으로 페이지·단·조각 결정
3. Render   SheetColumn + PassageBlock / QuestionBlock
```

- 측정은 `ExamSheet`의 숨은 MeasureLayer + 지문 조각 프로브(`measurePassage`)로 한다.
- 측정 레이어는 `h-0 w-0 overflow-hidden` 래퍼로 잘라내 **스크롤 영역을 늘리지 않는다**.
- 측정용 사본은 `anchor={false}` — `q-{id}` DOM id가 문서에 두 번 생기지 않게 한다.
- **그림은 높이를 항상 고정한다.** 이미지 로드 시점에 따라 높이가 변하면 측정·패킹 결과가 흔들린다.

## 데이터 계약

```ts
passages: { id, label, intro, body, questionIds[] }[]     // 없으면 []
questions: {
  id, stem, choices[5], answer, points,
  passageId?,        // 있으면 지문형, 없으면 단일 문제
  blocks?: QuestionContentBlock[]
}[]
```

### 문항 블록 (`blocks`) — 발문 아래에 순서대로 렌더

| type | 렌더 | 용도 |
|------|------|------|
| `general` | 테두리 박스 | 자료 본문, 학생 대화 |
| `table` | 테두리 표 | 자료 표 (`head?`, `rows`) |
| `figure` | 그림 | `srcs`(`public/figures/` 파일명), `labels`, **`height` 필수**, `stack`(세로 쌓기), `note`(그림 없을 때 자리 안내) |
| `text` | 테두리 없는 문단 | 질문 문장 — "이에 대한 설명으로 옳은 것만을 …" |
| `view` | `<보 기>` 박스 | ㄱ/ㄴ/ㄷ — 아래 [보기 박스](#보기-박스-viewbox) 참고 |

- 배점 표시(`[3점]`)는 **마지막 `text` 블록 끝**에 붙는다. `text` 블록이 없으면 발문 끝에 붙는다.
- `figure`의 `srcs`가 비어 있으면 `note` 문구와 함께 점선 상자로 **자리만 확보**한다.

#### 그림 크기

단 폭이 306.7이므로 **한 장은 그 폭이 상한**이다. `height`를 그보다 크게 줘도 `object-contain`이
가로에 맞춰 줄이므로 그림은 커지지 않고 위아래 빈 공간만 생긴다.

두 장을 가로로 나열하면 각 장이 **절반(≈149)** 까지만 커진다. 더 크게 보여야 하면 `stack: true`로
세로로 쌓는다 — 이때는 `height`가 곧 그림 크기다 (`한 장 높이 = (height − 33) / 2`).
현재 시험지의 (가)/(나)는 **가로 한 줄**이고, 남는 세로 공간이 생기지 않게 `height`를
그림 높이에 맞춰 둔다 (149 폭 · 비율 1.83 → 82 + 라벨 12.5 ≈ **95**).

원본 이미지는 **교재 PDF에서 다시 뽑는다.** 화면 캡처를 잘라 쓰면 둥근 모서리·흰 여백·테두리 회색
선이 섞여 들어온다. 번호(❶❷)가 붙은 도해는 임베드 이미지가 아니라 **페이지 영역을 고해상도로
렌더링**해야 한다 (번호는 페이지에 그려져 있다). 여러 장을 나란히 놓을 때는 **같은 비율·같은 픽셀
크기로 맞춰서** 저장한다 — 비율이 다르면 `object-contain`이 서로 다른 크기로 그린다.

## 모바일 페이지 규칙 (`MobileExamView`)

목표: 좁은 화면에서 **페이지 단위**로 문제를 넘긴다. 데스크톱 2단 패킹은 쓰지 않는다.

| 단위 | 한 페이지에 들어가는 내용 |
|------|---------------------------|
| 단일 문제 | 문제 **1개** (현재 시험지는 전부 이 형태 — 20문항 = 20페이지) |
| 지문 묶음 | 지문 + 그 지문의 `questionIds` 문제 전부 |

- **가로 스크롤** / 좌·우 터치 스와이프 (`scroll-snap`), 페이지 안에서는 세로 스크롤
- 넘기는 길은 **터치 스와이프와 키보드 `←` `→` 둘뿐**이다. 마우스 드래그는 두지 않는다 —
  서명 캔버스·선택지와 포인터를 두고 다퉜다
- 흰 바탕은 종이가 직접 깐다 (`<article>` 이 아니라 안쪽 종이) — 종이가 화면보다 짧으면
  위아래로 `body` 의 모눈종이가 드러나 PC 와 같은 책상이 된다
- 문제 본문은 오른쪽에도 `BODY_INDENT`(11.3) 만큼 여백을 준다 — 문제 블록이 왼쪽만
  들여쓰고 상자는 단 오른쪽 끝까지 닿아서, 옆 단이 없는 모바일에서는 보기 박스가
  오른쪽으로 밀려 보인다. 데스크톱 2단은 레퍼런스대로 두고 모바일에서만 맞춘다
- 1페이지: PC와 동일한 첫 장 헤더 / 2페이지~: 속지 헤더
- 표지에서 서명하기 전에는 문제 페이지를 붙이지 않는다
- **마지막 페이지**: `제출` 버튼 — 제출하면 채점 화면을 거쳐 성적통지표로 넘어간다 (RESULT-PAGE.md)

구현: `src/components/MobileExamView.tsx` (`buildMobilePages`)

## 하지 않는 것

- 문제 본문을 단 중간에 잘라 이어 붙이기
- 단별 left/right 수동 지정
- 그림 높이를 비워 두기 (측정이 흔들린다)
- 지문 박스와 가운데 세로선을 강제로 한 선으로 합치기 (거터 `COLUMN_GUTTER` 유지)
- 모바일에서 지문 묶음 문제를 페이지마다 쪼개기 / 단일 문제를 여러 개 한 페이지에 넣기
