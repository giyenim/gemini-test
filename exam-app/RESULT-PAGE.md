## 0. 이름 — 표지에 직접 쓴다

**별도 입력 화면은 없다.** 실제 시험지처럼 표지부터 바로 시작하고, 이름은 표지의
**성명 칸에 직접 적는다.** 적는 즉시 속지 헤더와 성적표에 반영된다.

수험 번호는 표지를 여는 순간 자동 발급한다 (`examinee.ts`).

수험 번호는 **8자리 난수**다 (기입 칸이 4–4 라 자릿수는 여기에 묶여 있다).

쓰임새는 하나 — **같은 성적표로 두 번 응모했는지 가려내는 것**이다. 응모를 받는 쪽에서
번호가 같으면 같은 응시, 다르면 다른 응시로 친다. 겹칠 확률은 응시자 1,000명이면 0.5%,
5,000명이면 12%, 10,000명이면 39% 로 **명단 어딘가 한 쌍**이 겹치는 정도다(생일 문제).
응모자 명단에서 중복을 거르는 용도로는 이 정도면 된다.

> **위조를 막지는 못한다.** 번호를 만드는 것이 브라우저라서, 홈 링크를 다시 눌러 새 번호를
> 받거나 캡처 이미지의 숫자를 고치는 것은 걸러내지 못한다. 거기까지 필요해지면 서버가
> 번호를 발급하고 대조해야 한다(§8 "서버") — 그때 DB 에 unique 제약과 충돌 시 재발급을 둔다.

앞 4자리에 응시 시각을 넣던 것은 걷어냈다. 같은 시간대 응시자끼리 앞자리가 뭉쳐 서로
비슷해 보였고, 번호에서 응시 시각이 역산됐다. 캡처되어 공유되는 물건이라 필요 없는
정보는 담지 않는다.

- 적은 이름은 시험지 첫 장 헤더의 **성명란**(`SheetHeaderFirst` 셋째 줄)에 그대로 들어간다.
  실제 수능도 표지와 속지 양쪽에 성명란이 있다.
- 성적표에도 같은 이름·번호가 찍힌다. 시험지와 성적표가 한 세트로 보이게 하는 장치다.
- 본문과 **다른 글꼴**(`--font-write`)로 렌더한다. 인쇄된 양식 위에 적어 넣은 칸으로 보여야 한다.
  이 자리에는 나중에 **실제 사용자 손글씨**가 들어갈 예정이다. 그때까지는 굴림으로 둔다.

## 결과 페이지의 주소 — `/?done`

성적표는 **제 주소를 가진다.** 제출하는 순간 `/?done` 으로 넘어가므로, 새로고침하거나
뒤로가기를 눌러도 스무 문제를 다시 풀지 않는다.

| 주소 | 하는 일 |
|------|---------|
| `/` | **늘 새 시험지.** 낸 기록이 있어도 지우지는 않고 그대로 둔다 |
| `/?done` | 성적표. 낸 기록이 없으면 `/` 로 갈아 끼운다 |

**어느 화면을 열지는 주소가 정한다.** 저장된 기록은 성적표를 그릴 재료일 뿐이다.
그래서 성적표에서 뒤로가면 새 시험지가 열리고, 거기서 앞으로가면 성적표가 다시 선다 —
기록을 지우지 않고 두는 것이 이 왕복을 가능하게 한다. 홈 링크를 다시 눌러도 새 시험지다.

경로(`/result`)가 아니라 **쿼리**인 것은 GitHub Pages 가 정적 파일만 내주기 때문이다 —
`/result` 로 직접 들어오면 그런 파일이 없어 404 가 난다. 쿼리는 어느 정적 호스팅에서나
`index.html` 로 그대로 떨어진다 (`src/route.ts`).

**저장하는 것은 제출 순간의 답안·응시자뿐이다** (`src/session.ts`). 풀던 도중의 답안은
담지 않아 시험 중 새로고침은 예나 지금이나 처음부터다. 점수도 담지 않는다 — 답안과
문제지가 있으면 `gradeExam` 이 같은 값을 다시 낸다.

자리는 `sessionStorage` 다. 수명이 **탭 하나**여서 탭을 닫으면 지워진다 — 공용 PC 에
앞사람 성적표가 남지 않고, 새 탭은 곧 새 응시다. 저장이 막힌 브라우저(사생활 보호 모드
등)에서도 응시는 막지 않는다. 그 탭에서만 새로고침에 결과가 날아갈 뿐이다.

> 낸 답을 고쳐 다시 내는 길은 없다 — 뒤로가면 앞 응시가 이어지는 것이 아니라 **처음부터
> 새 시험**이고, 수험 번호도 새로 발급된다. 앞 응시의 성적표는 앞으로가기로만 돌아온다.
> 새 응시를 제출하면 그것이 기록을 덮어쓴다.
>
> `채점 중` 3초는 되살리지 않는다 — 지나가는 연출이라 되감을 것이 없고, 새로고침한
> 사람을 3초 더 세워 둘 이유도 없다.

## 1. 화면 구성

```
┌────────────────────────────────┐
│                                │
│        성적통지표 카드          │
│                                │
│      문항별 채점표 ↗            │   ← 팝업 (카드 안)
│      오답노트 ↗                 │   ← 팝업 (카드 안)
└────────────────────────────────┘

        ┌──────────────────────┐
        │  📖 책 보러가기   │        ← 버튼 (외부 링크)
        └──────────────────────┘
```

- **종이를 깔지 않는다.** 시험을 마친 화면이라 성적표 카드와 버튼이 책상(모눈·표지 벽지)
  위에 그대로 놓인다. 흰 바탕은 카드가 제 몫으로 가지고 있다. 시험지와 같은 842 폭만
  지켜 앞 화면들과 같은 자에 맞춘다 (`ResultView`).
- 성적표 카드 하나가 본문을 독점한다. 채점표·오답노트는 **전부 팝업**으로 뺀다.
- 앞의 세 개는 **텍스트 링크**, 마지막 책만 **버튼**이다. 색도 책만 포인트 컬러, 나머지는 먹색.
- **세로로 쌓고 가운데 정렬.** 성적표 폭 안에 두면 성적표 하단 안내문처럼 보여 톤이 맞는다.
  가로로 늘어놓지 않는다 — 세로로 긴 문서라 톤이 깨진다.
- 순서를 바꾸지 않는다: 확인 → 복습 → 저장 → 구매.

### 제출 → 성적표 전환

즉시 띄우지 말고 **`채점 중` 화면**을 거쳐 성적표가 나타난다. 체감을 크게 올리는 싼 연출이다.

화면은 문구 한 줄과 그 아래 **채워지는 띠**(`ui/ProgressBar`) 뿐이다. 종이를 깔지 않는다 —
채점은 시험지 위에서 일어나는 일이 아니라 앞뒤 화면과 같은 책상(모눈·표지 벽지) 위에 둔다.
문구는 시험지 밖의 글자라 화면 글꼴(Pretendard)이다. 명조는 종이 위에서만 쓴다.
획은 SVG 필터로 **물결에 담근 것처럼** 흐물흐물하게 흔든다 — 잦기는 낮게(1 옥타브),
폭은 크게. 잦기를 올리면 물결이 아니라 지직거리는 노이즈가 된다.

**띠 크기는 480×46 이다.** 속(획 안쪽)이 36px 이라 **16px 글월**의 줄상자(24px) 위아래로
6px 씩 남는다. 폭은 `PROGRESS_BAR_W` 한 곳에서 오고, 띠의 좌표계와 같은 값이라야 1:1 로
그려진다 — 담는 자리만 넓히면 둥근 끝이 옆으로 눌린 타원이 되므로 **크기를 바꿀 때는
`ProgressBar` 의 좌표계와 path 를 같이 고친다.**

글월은 `ProgressBar` 의 `children` 으로 넣으면 띠 **안** 가운데에 앉는다. 채움(밝은 회색)과
빈 자리(흰색) 어느 쪽에 걸쳐도 먹색 글자는 읽히므로, 채움이 지나가도 글자를 손볼 일이 없다.

### 띠 안의 문구

`GRADING_MESSAGES` 를 `MESSAGE_MS`(1200) 씩 차례로 보여 준다. 채점기가 하는 일을 순서대로
읊어, 기다리는 시간이 빈 시간이 아니라 무언가 진행되는 시간으로 읽히게 한다.

- **대기 시간은 문구 수에서 나온다** — `GRADING_MS = 문구 수 × MESSAGE_MS`. 문구를 더하거나
  빼면 대기 시간도 따라온다. 따로 적으면 마지막 문구가 읽히기 전에 넘어가거나 빈 시간이 남는다.
- **한 줄은 띄어쓰기까지 18자를 넘기지 않는다.** 띠 안쪽이 가장 좁은 화면(320px)에서 224px 이고
  16px 글자가 자당 11.7px 이라 19자에서 넘친다. `whitespace-nowrap` 이라 넘치면 잘려 보인다.
- 넘어가는 모습은 **위로 미끄러짐**이다. 줄을 전부 이어 붙여 두고 띠 전체를 밀어 올린다 —
  보이는 줄만 갈아 끼우면 앞 문구가 나가는 모습이 없어 툭 바뀐다.
- 미는 거리는 `문구 차례 × 줄 높이(24px)` 다. 문구마다 머무는 시간이 같으므로 차례는 진행률에서
  그대로 나온다 — 시계를 따로 두지 않아 어느 시점을 집어도 그 자리의 문구가 나온다.
- 움직임을 줄이는 설정(`prefers-reduced-motion`)이면 미끄러지지 않고 바로 갈린다.

**3초는 `components/result/constants.ts` 의 `GRADING_MS` 한 곳에서 온다.** 화면을 넘기는
`App` 의 타이머와 띠가 같은 값을 봐야 한다 — 따로 두면 띠가 덜 찬 채로 넘어가거나 다 찬
뒤 빈 시간이 남는다. 띠는 `setInterval` 로 칸을 세지 않고 프레임마다 흐른 시간을 재서
채운다 (탭이 잠들었다 깨도 실제 시간을 따라간다).

## 2. 성적통지표 카드

수능 성적통지표 양식을 그대로 재현한다. 카드 안의 모든 글자는 글꼴·굵기 하나(`CARD_TEXT`)를
쓰고 크기만 다르다. 폭은 `CARD_W` 한 곳에서 정한다.

```
┌──────────────────────────────────────────────┐

│                 성적통지표                    │
│                                              │
│  성명 ㅇㅇㅇ           수험번호 25010812      │
│  ┌────────┬──────┬────────┬──────┬────┐      │
│  │  영역  │원점수│표준점수│백분위│등급│      │
│  ├────────┼──────┼────────┼──────┼────┤      │
│  │제미나이│34/50 │  118   │  87  │ 2  │      │
│  │  활용  │      │        │      │    │      │
│  └────────┴──────┴────────┴──────┴────┘      │
│                                              │
```

| 항목 | 내용 |
|------|------|
| 표 열 | 영역 / 원점수 / 표준점수 / 백분위 / 등급 |
| 강조 | **등급을 가장 크게.** 원점수보다 등급이 공유 욕구를 만든다 |
| 하단 | 시험 날짜(응시일) + 기관명 |
| 기관명 | **이지스퍼블리싱**을 평가원처럼 쓴다. 관인처럼 글자 사이를 한 칸씩 벌린다 |
| 카드 안 링크 | `<문항별 채점표 보기>` · `<오답노트 보기>` — 카드 글꼴·크기를 그대로 물려받는다 |

### 모바일 (≤767px)

같은 카드를 그대로 쓰고 `md:` 로 **PC 쪽만 예외를 준다** — 좁은 화면이 기본형이다.

| 자리 | 모바일 | PC (`md:`) |
|------|--------|-----------|
| 카드 좌우 여백 | `px-5` | `px-8` |
| 제목 | 18px, 두 줄로 갈림 (`word-break: keep-all`) | 24px, 한 줄 고정 |
| 성명 · 수험번호 | ← 화면 크기로 가르지 않는다. 폭이 어떻든 양 끝으로 갈라 한 줄이고, 둘이 닿을 때에만 `flex-wrap` 이 두 줄로 내린다 →|
| 카드 안 링크 둘 | 한 줄씩 가운데 | 가로로 나란히 |
| 응시일 | 14px | 20px |
| 기관명 | 16px | 30px |

기관명을 많이 줄이는 것은 글자 사이를 벌려 둬서 같은 글자 수보다 1.5배쯤 길기 때문이다.
**두 줄로 갈리면 관인으로 보이지 않는다.**

### 백분위 — 서버 기록 기반 실제 값

> **지금은 기준 분포로 계산한다.** `grade.ts`의 `BASE_MEAN`(30) · `BASE_SD`(9)를
> 모집단으로 두고 표준점수 `20z+100`, 백분위 `Φ(z)`, 등급은 누적 비율
> (4/11/23/40/60/77/89/96%)로 낸다. 근거가 되는 응시 데이터는 없는 값이다.
>
> **이 고정값으로 간다 (2026-09-03 결정).** 지표 수집(`src/analytics.ts`)이 제출마다
> 원점수를 남기고 있어 실제 분포를 낼 수는 있지만, 그것으로 갈아끼우지 않는다.
>
> 응시자가 적을 때 실제 분포를 쓰면 등급이 표본을 따라 출렁인다 — 같은 점수가 어제는
> 3등급, 오늘은 5등급이 된다. 성적표는 캡처되어 공유되는 물건이라 그 흔들림이 곧 신뢰를
> 깎는다. 고정값은 근거가 없는 대신 **누구에게나 같은 자를 댄다.**
>
> 아래 §"백분위 — 서버 기록 기반 실제 값"의 계획은 **보류**다. 되살리려면 표본이 충분히
> 쌓인 뒤라야 하고, 그때는 등급이 응시 시점에 따라 달라진다는 것을 감수해야 한다.

> 아래는 **보류된 원안**이다 (2026-09-03). 지우지 않고 두는 것은, 되살릴 때 여기 적힌
> 판단이 그대로 쓸모 있기 때문이다 — 특히 "표본 미달 시 대체"가 지금 결정의 이유이기도 하다.

~~가상 분포를 쓰지 않는다.~~ **응시 결과를 서버에 기록하고 실제 응시자 대비 백분위를 계산**한다.

- 표준점수·등급도 같은 분포에서 산출한다. 등급컷은 누적 비율(4%/11%/23%…) 기준이 자연스럽다.

> 서버 스키마·API는 미정. 최소한 `{ 이름, 수험번호, 원점수, 문항별 정오, 응시시각 }`은 남긴다.

## 3. 팝업 ① 문항별 채점표

기존 `AnswerKeyView`(정답표)를 여기에 흡수한다. 정답표는 `문항/정답/배점`이고 채점표는 거기에
`내 답`과 `○✕`를 더한 것이라 **완전히 포함**된다. 별도 화면을 남기지 않는다.

### 늘 펼친 하나 (2026-08-23)

축소·확대 토글을 없앴다. 접어 두면 결국 다시 펴게 되고, 두 모습을 맞추느라 칸 크기가
양쪽에 묶였다. 지금은 **문항 번호 + `○`/`✕` + 내 답 / 정답 / 배점**을 늘 함께 보여 준다.

창은 UI 킷의 손그림 종이(`ui/PaperWindow`)를 쓴다 — 서명 창과 같은 윤곽이고,
제목 줄에 구분선을 긋지 않으며 닫기는 손그림 `✕` 하나다. `Modal` 은 껍데기 없이(`bare`)
어둡게 깔기 · Esc · 바깥 누르기 · 스크롤 잠금만 맡는다.

| 규칙 | 값 |
|------|-----|
| 칸에 담기는 것 | 문항 번호 + `○`/`✕` + 내 답 / 정답 / 배점 |
| 미선택 | `—` 로 표시 — 찍어서 틀린 것과 못 푼 것을 구분한다 |
| 오답 칸 | 붉은 테두리와 붉은 `✕` 로만 가른다 — 바탕은 정답 칸과 같은 흰색 |
| 오답 칸 클릭 | **없음** — 칸은 읽는 것이고, 오답노트로 가는 길은 성적표의 링크 하나뿐이다 |
| 열 수 | 문항 수가 20이 아니어도 **4열 고정**, 행만 늘린다 |
| 모바일 | 2열로 떨어뜨린다 |

## 4. 팝업 ② 오답노트

**한 문제씩 넘겨 본다.** 목록으로 쌓지 않는다.

```
┌──────────────────────────────┐
│  오답노트          2 / 7   ✕ │
├──────────────────────────────┤
│  7번  [3점]                  │
│  ┌────────────────────────┐  │
│  │  문항 전문 (시험지 그대로)│  │
│  └────────────────────────┘  │
│  내 답 ①   /   정답 ④        │
│  ──────────────────────────  │
│  해설)                       │
│  두세 줄…                     │
│  출처) 3장 … (p.55)          │
├──────────────────────────────┤
│  ‹ 이전   2·7·11·14·16   다음 ›│
└──────────────────────────────┘
```

- **문항 전문을 다시 보여준다.** 요약만 있으면 뭘 틀렸는지 기억나지 않는다.
- `QuestionBlock`을 그대로 재활용한다. 이 컴포넌트는 **단 폭 318px 기준**으로 만들어졌으므로
  **모달 본문 폭을 318px 근처로 잡으면 레이아웃이 깨지지 않는다.** (LAYOUT.md의 `columnWidth()`)
- 넘기는 길: **PC 는 좌우 화살표와 키보드 `←` `→`, 모바일은 스와이프**다. 모바일에서는
  화살표를 숨긴다 — 좁은 창에서 종이 가장자리에 얹히면 문항 글자와 다툰다. 대신 본문
  아래에 `좌우로 밀어서 넘기기` 한 줄을 둔다. 닫기는 `ESC`.
- **해설과 출처는 `머리말)` 로 연다** — `해설)` `출처)`. 어디부터 무엇인지 한 덩어리로 알린다.
  해설의 머리말은 **제 줄을 차지한다** — 여러 줄짜리 해설(ㄱ/ㄴ/ㄷ)에서 머리말을 첫 줄에
  얹으면 ㄱ 만 안쪽으로 밀려 ㄴ·ㄷ 와 어긋난다. 한 줄짜리인 출처는 머리말을 같은 줄에 둔다.
- **출처 줄은 해설과 확실히 갈라 둔다.** 바로 밑에 같은 크기·색으로 두면 해설의 마지막
  문단으로 읽힌다 (장 제목이 길어 두 줄이 되면 특히). 머리말에 더해 간격·크기·색
  (`--color-source`) 세 가지로 더 가른다.
- 하단 인디케이터는 점이 아니라 **틀린 문항 번호**로 둔다. 바로 점프할 수 있고 몇 번을 틀렸는지도 보인다.
- **마지막 오답이 마지막 장이다** (2026-08-23). 넘기다 도착하던 책 안내 장은 뺐다 —
  책으로 가는 길은 성적표 화면의 링크 하나로 모았다.

### 필요한 데이터 — 채웠다

`src/data/exam-sample.json`의 문항마다 아래 두 개가 있다. **20문항 전부 채웠고**,
근거는 [`exam/후보문항.md`](../exam/후보문항.md)의 해설·출처다.

| 필드 | 내용 |
|------|------|
| `explanation` | 해설 2~3줄. 줄바꿈으로 항목(ㄱ/ㄴ/ㄷ, A/B/C)을 나눈다 |
| `source` | `{ chapter, detail }` — 예: `01장 안녕, 제미나이!` / `01-4 (p.43~44)` |

문구는 검수가 필요하다. 문항을 교체하면 이 두 필드도 함께 채운다.

### 🎁 특별자료 받기 (버튼) — **한시적**

이벤트 기간에만 두는 버튼이다. 같은 손그림 버튼 셋째 자리에 앉고, 누르면
채점표·오답노트와 같은 손그림 종이 창(`BonusPopup`)이 뜬다. 창은 안내를 읽히고,
**`네! 완료했어요!` 를 누르면 그 자리가 링크로 바뀐다.**

공유했는지는 확인할 방법이 없다. 이 한 번은 검사가 아니라 **한 번 더 눈에 밟히게 하는
장치**다 — 스스로 누르는 동작이 공유를 떠올리게 한다. 누르지 않아도 막을 것은 없고,
막을 수도 없다. **네모 칸은 두지 않는다** — 브라우저가 그리는 네모는 손그림 종이 위에서
혼자 각지고, 켜고 끄는 칸처럼 보여 되돌릴 수 있다는 오해를 준다. 두 상태가 같은 자리를
나눠 쓰되 그 자리 높이를 고정해 갈아끼울 때 창이 출렁이지 않는다.

링크는 새 탭을 대신 열어 주지 않는다 — 팝업 차단에 걸리면 아무 일도 없었던 것처럼
보이기 때문이다. 창 안에서 유일하게 파란색(`text-blue-700`)이고 밑줄을 늘 달고 있다 —
손그림 종이 위에서 이것만 바깥으로 나가는 길이라 웹의 관습대로 두어 한눈에 갈린다.
글자 무게는 본문과 같다(400).

안내 줄의 간격은 **모든 줄이 같다.** 특정 줄만 좁히면(한때 이모티콘 줄이 그랬다) 문구를
고칠 때 그 규칙이 엉뚱한 줄에 걸려 간격이 들쭉날쭉해진다 — 줄 수와 무관하게 한 값으로 둔다.

문구·주소는 전부 `constants.ts` 의 특별자료 절에 모여 있다 (`BONUS_URL`·`BONUS_TITLE`·
`BONUS_LINES`·`BONUS_CHECK_LABEL`·`BONUS_LINK_LABEL`). 컴포넌트를 열지 않고 고칠 수 있다.

> **주소는 비밀이 아니다.** 번들에 문자열로 박히므로 응시하지 않은 사람도 찾아낼 수 있고,
> 받은 사람이 퍼뜨릴 수도 있다. "이벤트 참여자에게만"은 실제 통제가 아니라 안내다.
> 기간이 끝나 확실히 닫으려면 앱이 아니라 **Drive 쪽에서 공유를 해제**한다 —
> 버튼을 내려도 이미 퍼진 주소는 계속 열린다.

**걷어낼 때**: `result/BonusPopup.tsx` 삭제 · `ResultView` 의 버튼과 `popup` 갈래 제거 ·
`constants.ts` 의 특별자료 절 삭제 · `analytics.ts` 의 `ClickTarget` 에서 `'bonus'` 제거 ·
이 절 삭제.

- 친구에게 도전장 (내 점수가 담긴 공유 링크)
