# 결과 페이지 (성적통지표) 명세 — 핸드오프

시험 제출 직후 보게 되는 화면. **이 콘텐츠에서 가장 오래 머무는 화면이자 유일한 공유 대상**이다.
목적은 두 가지 — ① 성적표 이미지가 SNS로 퍼져 책을 알린다 ② 오답을 통해 책 구매로 이어진다.

> 시험지 레이아웃 규칙은 [LAYOUT.md](./LAYOUT.md)를 본다. 이 문서는 **제출 이후 화면**만 다룬다.

---

## 이 화면만 열기 — `?result`

고칠 때마다 스무 문제를 찍고 채점 3초를 기다리지 않는다. 주소에 `?result` 를 붙이면
표지·시험지·채점을 건너뛰고 **결과 화면부터** 열린다 (`components/result/ResultPreview.tsx`).

| 주소 | 보이는 것 |
|------|-----------|
| `?result` | 13문항 정답 — 7오답(그중 하나는 미선택) |
| `?result=17` | 17문항 정답 |
| `?result=perfect` | 만점 — 오답노트가 잠긴 모습 |
| `?result=0` | 0점 — 오답노트 20문항 |
| `?result=grading` | `채점 중` 화면 (넘어가지 않고 머문다) |

성명 서명은 견본 획을 하나 그려 넣는다 — 빈 칸으로 두면 이름 자리의 균형을 볼 수 없다.
그려지는 것은 실제 `ResultView` 그대로라, 여기서 고친 것이 곧 응시자가 보는 것이다.

### 글꼴

| 쓰임 | 변수 | 글꼴 |
|------|------|------|
| 시험지·본문 전체 | `--font-serif` | **Noto Serif KR** (400/600/700) |
| 양식(시험지 헤더·성적통지표 카드) | `--font-gothic` | **조선굴림** (ChosunGu) |
| 응시자 기입란 (이름·수험 번호) | `--font-write` | **조선굴림** |

인쇄된 시험지(명조)와 관공서가 발급한 통지표(굴림)라는 차이를 글꼴로 준다. 기입란은 양식 위에
적어 넣은 칸이라 본문과 다른 글꼴을 쓴다 — **나중에 실제 사용자 손글씨가 들어갈 자리**이므로
그때까지만 굴림이다.

> 본문도 조선신명조로 바꿔 봤으나 **되돌렸다.** 가로획이 얇아 11.5px 본문이 자글거렸고,
> 굵기 파일이 400 한 벌뿐이라 `font-bold` 가 전부 브라우저 합성(가짜 볼드)이 됐다.
> Noto Serif KR 은 화면용 힌팅이 촘촘하고 400/600/700 이 실제로 있다.
> **조선굴림은 성적표에만 남긴다** — 여기도 굵기는 400 하나뿐이라 볼드는 합성이다.

조선굴림은 방일영문화재단이 개인·기업 무료로 배포하며 재배포·임베딩을 허용한다.
**저장소 안의 서브셋**(`public/fonts/ChosunGu-subset.woff2`, 67KB)을 woff2 한 벌만 둔다 —
CDN 원본(1,441KB)을 두면 전송량이 그만큼 늘어난다 (`index.css` @font-face 주석 참고).

## 0. 이름 — 표지에 직접 쓴다

**별도 입력 화면은 없다.** 실제 시험지처럼 표지부터 바로 시작하고, 이름은 표지의
**성명 칸에 직접 적는다.** 적는 즉시 속지 헤더와 성적표에 반영된다.

수험 번호는 표지를 여는 순간 자동 발급한다 (`examinee.ts`).

수험 번호는 8자리다 (앞 4자리 = 응시 시각, 뒤 4자리 = 난수). 나중에 **DB 에서 응시 건을
구분하는 값**으로 쓴다. 다만 10⁸ 공간이라 응시자가 1만 명이면 생일 문제로 충돌이 한 번쯤
나온다 — **DB 에 unique 제약을 걸고 충돌 시 재발급하는 처리가 서버에 필요하다.**

- 적은 이름은 시험지 첫 장 헤더의 **성명란**(`SheetHeaderFirst` 셋째 줄)에 그대로 들어간다.
  실제 수능도 표지와 속지 양쪽에 성명란이 있다.
- 성적표에도 같은 이름·번호가 찍힌다. 시험지와 성적표가 한 세트로 보이게 하는 장치다.
- 본문과 **다른 글꼴**(`--font-write`)로 렌더한다. 인쇄된 양식 위에 적어 넣은 칸으로 보여야 한다.
  이 자리에는 나중에 **실제 사용자 손글씨**가 들어갈 예정이다. 그때까지는 굴림으로 둔다.

## 1. 화면 구성

```
┌────────────────────────────────┐
│                                │
│        성적통지표 카드          │
│                                │
│      문항별 채점표 ↗            │   ← 팝업 (카드 안)
│      오답노트 ↗                 │   ← 팝업 (카드 안)
└────────────────────────────────┘

        ┌──────────────────────┐
        │  📖 책에서 확인하기   │        ← 버튼 (외부 링크)
        └──────────────────────┘
```

- 성적표 카드 하나가 본문을 독점한다. 채점표·오답노트는 **전부 팝업**으로 뺀다.
- 앞의 세 개는 **텍스트 링크**, 마지막 책만 **버튼**이다. 색도 책만 포인트 컬러, 나머지는 먹색.
- **세로로 쌓고 가운데 정렬.** 성적표 폭 안에 두면 성적표 하단 안내문처럼 보여 톤이 맞는다.
  가로로 늘어놓지 않는다 — 세로로 긴 문서라 톤이 깨진다.
- 순서를 바꾸지 않는다: 확인 → 복습 → 저장 → 구매.

### 제출 → 성적표 전환

즉시 띄우지 말고 **`채점 중입니다` 3초** 후 성적표가 나타난다. 체감을 크게 올리는 싼 연출이다.

## 2. 성적통지표 카드

수능 성적통지표 양식을 그대로 재현한다. 카드 안의 모든 글자는 글꼴·굵기 하나(`CARD_TEXT`)를
쓰고 크기만 다르다. 폭은 `CARD_W` 한 곳에서 정한다.

```
┌──────────────────────────────────────────────┐
│        2026학년도 제미나이 활용 능력 시험      │
│                 성적통지표                    │
│                                              │
│  수험번호 25010812      성명 ㅇㅇㅇ           │
│  ┌────────┬──────┬────────┬──────┬────┐      │
│  │  영역  │원점수│표준점수│백분위│등급│      │
│  ├────────┼──────┼────────┼──────┼────┤      │
│  │제미나이│34/50 │  118   │  87  │ 2  │      │
│  │  활용  │      │        │      │    │      │
│  └────────┴──────┴────────┴──────┴────┘      │
│                                              │
│              2026년 8월 6일                   │
│         이지스퍼블리싱 ○○평가원  (印)         │
└──────────────────────────────────────────────┘
```

| 항목 | 내용 |
|------|------|
| 표 열 | 영역 / 원점수 / 표준점수 / 백분위 / 등급 |
| 강조 | **등급을 가장 크게.** 원점수보다 등급이 공유 욕구를 만든다 |
| 하단 | 시험 날짜(응시일) + 기관명 |
| 기관명 | **이지스퍼블리싱**을 평가원처럼 쓴다. 관인처럼 글자 사이를 한 칸씩 벌린다 |
| 표 아래 | 원점수·표준점수·백분위·등급을 실제 계산 그대로 풀어 쓴 설명 4줄 (`NOTES`) |
| 카드 안 링크 | `문항별 채점표 ↗` · `오답노트 ↗` — 카드 글꼴·크기를 그대로 물려받는다 |

### 모바일 (≤767px)

같은 카드를 그대로 쓰고 `md:` 로 **PC 쪽만 예외를 준다** — 좁은 화면이 기본형이다.

| 자리 | 모바일 | PC (`md:`) |
|------|--------|-----------|
| 카드 좌우 여백 | `px-5` | `px-8` |
| 제목 | 18px, 두 줄로 갈림 (`word-break: keep-all`) | 24px, 한 줄 고정 |
| 수험번호 · 성명 | 한 줄씩 세로 | 양 끝으로 갈라 한 줄 |
| 카드 안 링크 둘 | 한 줄씩 가운데 | 가로로 나란히 |
| 응시일 | 14px | 20px |
| 기관명 | 16px | 30px |

기관명을 많이 줄이는 것은 글자 사이를 벌려 둬서 같은 글자 수보다 1.5배쯤 길기 때문이다.
**두 줄로 갈리면 관인으로 보이지 않는다.**

### 백분위 — 서버 기록 기반 실제 값

> **지금은 기준 분포로 계산한다.** 서버가 없어 실제 응시자 분포를 쓸 수 없다.
> `grade.ts`의 `BASE_MEAN`(30) · `BASE_SD`(9)를 모집단으로 두고 표준점수 `20z+100`,
> 백분위 `Φ(z)`, 등급은 누적 비율(4/11/23/40/60/77/89/96%)로 낸다. 근거가 되는 응시
> 데이터는 없는 값이다. 서버가 붙으면 이 두 상수를 실제 통계로 갈아끼운다.

가상 분포를 쓰지 않는다. **응시 결과를 서버에 기록하고 실제 응시자 대비 백분위를 계산**한다.

- 표준점수·등급도 같은 분포에서 산출한다. 등급컷은 누적 비율(4%/11%/23%…) 기준이 자연스럽다.
- 응시자가 적은 초기에는 값이 튀므로 **최소 표본 미달 시 기준 분포로 대체**하는 처리가 필요하다.
- 카드 아래 한 줄로 `오늘 1,284명 응시 · 평균 31.2점`을 넣는다. 백분위가 진짜라는 근거가 되고,
  숫자가 클수록 공유율이 올라간다.

> 서버 스키마·API는 미정. 최소한 `{ 이름, 수험번호, 원점수, 문항별 정오, 응시시각 }`은 남긴다.

## 3. 팝업 ① 문항별 채점표

기존 `AnswerKeyView`(정답표)를 여기에 흡수한다. 정답표는 `문항/정답/배점`이고 채점표는 거기에
`내 답`과 `○✕`를 더한 것이라 **완전히 포함**된다. 별도 화면을 남기지 않는다.

### 늘 펼친 하나 (2026-08-23)

축소·확대 토글을 없앴다. 접어 두면 결국 다시 펴게 되고, 두 모습을 맞추느라 칸 크기가
양쪽에 묶였다. 지금은 **문항 번호 + `○`/`✕` + 내 답 / 정답 / 배점**을 늘 함께 보여 준다.

창은 UI 킷의 손그림 종이(`ui/PaperWindow`)를 쓴다 — 서명 창과 같은 윤곽이고,
제목 줄에 구분선을 긋지 않으며 닫기는 손그림 `✕` 하나다. `Modal` 은 껍데기 없이(`bare`)
어둡게 깔기 · Esc · 바깥 누르기 · 스크롤 잠금만 맡는다.

| 규칙 | 값 |
|------|-----|
| 칸에 담기는 것 | 문항 번호 + `○`/`✕` + 내 답 / 정답 / 배점 |
| 미선택 | `—` 로 표시 — 찍어서 틀린 것과 못 푼 것을 구분한다 |
| 오답 칸 | 붉은 테두리와 붉은 `✕` 로만 가른다 — 바탕은 정답 칸과 같은 흰색 |
| 오답 칸 클릭 | **없음** — 칸은 읽는 것이고, 오답노트로 가는 길은 성적표의 링크 하나뿐이다 |
| 열 수 | 문항 수가 20이 아니어도 **4열 고정**, 행만 늘린다 |
| 모바일 | 2열로 떨어뜨린다 |

## 4. 팝업 ② 오답노트

**한 문제씩 넘겨 본다.** 목록으로 쌓지 않는다.

```
┌──────────────────────────────┐
│  오답노트          2 / 7   ✕ │
├──────────────────────────────┤
│  7번  [3점]                  │
│  ┌────────────────────────┐  │
│  │  문항 전문 (시험지 그대로)│  │
│  └────────────────────────┘  │
│  내 답 ①   ·   정답 ④        │
│  ──────────────────────────  │
│  해설 두세 줄…                │
│  📖 3장 — 문서와 이미지 다루기 │
├──────────────────────────────┤
│  ‹ 이전   2·7·11·14·16   다음 ›│
└──────────────────────────────┘
```

- **문항 전문을 다시 보여준다.** 요약만 있으면 뭘 틀렸는지 기억나지 않는다.
- `QuestionBlock`을 그대로 재활용한다. 이 컴포넌트는 **단 폭 318px 기준**으로 만들어졌으므로
  **모달 본문 폭을 318px 근처로 잡으면 레이아웃이 깨지지 않는다.** (LAYOUT.md의 `columnWidth()`)
- 좌우 화살표 + 모바일 스와이프 + 키보드 `←` `→`, `ESC` 닫기.
- 하단 인디케이터는 점이 아니라 **틀린 문항 번호**로 둔다. 바로 점프할 수 있고 몇 번을 틀렸는지도 보인다.
- **마지막 오답이 마지막 장이다** (2026-08-23). 넘기다 도착하던 책 안내 장은 뺐다 —
  책으로 가는 길은 성적표 화면의 링크 하나로 모았다.

### 필요한 데이터 — 채웠다

`src/data/exam-sample.json`의 문항마다 아래 두 개가 있다. **20문항 전부 채웠고**,
근거는 [`exam/후보문항-40.md`](../exam/후보문항-40.md)의 해설·출처다.

| 필드 | 내용 |
|------|------|
| `explanation` | 해설 2~3줄. 줄바꿈으로 항목(ㄱ/ㄴ/ㄷ, A/B/C)을 나눈다 |
| `source` | `{ chapter, detail }` — 예: `01장 안녕, 제미나이!` / `01-4 (p.43~44)` |

문구는 검수가 필요하다. 문항을 교체하면 이 두 필드도 함께 채운다.

## 6. 예정 — 부정행위 감지 (아직 설계 전)

시험 중 탭 이탈을 감지해 경고하고, 누적되면 **성적표에 무효 처리 도장**을 찍는 기획이 예정되어 있다.

- 무효 문구가 들어갈 자리는 **그때 만든다** — `※ 부정행위 2회 적발 — 이 성적은 무효 처리되었습니다`.
  비고란을 미리 비워 두었더니 빈 칸이 카드를 헐겁게 만들어 걷어냈다 (2026-08-23)
- 무효 성적표는 **별도 디자인 분기**가 될 가능성이 높다. 만점보다 무효 처리가 더 많이 공유될 수 있다.
- 이 문서의 §2 카드 구조는 그 분기를 감당할 수 있게 잡는다.
